# Related Work 裁剪占比：本地固定样本对比

本次比较使用同一份缓存提取结果，只调整 Related Work 的预算策略，不调用 LLM。
基线为 `bee41be` 的章节均衡策略；对比对象是每篇合计最多 900 字符的 Related Work 策略。
样本来自 run `33941229270` 的十篇论文，其中九篇有可用 PDF，一篇下载失败，不计入比例。

## 统计口径

- “裁剪前”指这次调整前的章节均衡结果，不是更早的头尾截断版本。
- 占比 = Related Work 保留字符数 / 该篇全部选中正文字符数。
- 保留字符包含章节标签和省略标记，不是 token 数；不包含额外的 abstract、signals、prompt。
- Related Work 范围根据标题及可靠的编号/层级关系识别。子章节单独计数后求和，避免只统计父标题而漏掉相关工作正文。
- 原始字符是可用提取范围中的相关工作文本；源提取上限为前 15 页，不能当成完整论文统计。
- 这些是本地样本数据，不能直接当成远端最新运行的输入计数。

## 调整规则和限制

每篇正文超出预算时，Related Work 父节及可确认的子节合计最多 900 字符。
组内先尝试给每节最多 200 字符的基础空间，再按剩余长度分配；这部分也包含在 900 字符内。
普通未知章节仍有原来的基础预算。标题混合了 Related Work 和 Method 时，不自动按纯相关工作处理。
章节编号优先于不一致的 Markdown 字号，避免漏掉 QCell 这类父标题是三级、子标题却是二级的 PDF 转换结果。

900 是绝对字符上限，并不保证占实际输出的比例小于 5%；因为实际选中正文可能少于 18k。
文章短到可以完整保留时，不额外裁掉 Related Work。特殊标题或层级不明确时可能漏识别，诊断不代表完整语义分类。
Related Work 有助于判断新颖性，因此默认保留少量内容。腾出的预算重新分配给其他正文，不承诺调用费用按同等比例下降。
